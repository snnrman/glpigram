# GLPIgram

> 🇬🇧 [Read in English](README.md)

**GLPIgram** — Telegram-бот для ITSM на базе **GLPI 11** (legacy REST API v1). Сотрудники
создают и отслеживают заявки прямо из Telegram; техники получают уведомления в
группе и управляют очередью инлайн-кнопками — без плагинов на стороне GLPI, без
входящих портов, только long polling.

## Возможности

- **Создание заявок** — пошаговый диалог: категория (живой список из GLPI) →
  срочность → заголовок → описание → фото/документы → подтверждение. Свободный
  текст боту тоже предлагает стать заявкой.
- **Привязка аккаунтов (через AD)** — пользователь представляется AD-логином
  *или* ФИО; техник подтверждает привязку одной кнопкой в группе поддержки
  (защита от подмены). Отключённые в GLPI/AD аккаунты отвязываются
  автоматически.
- **Мои заявки** — список открытых заявок с детальным видом (статус,
  исполнитель, последние комментарии, ссылка на GLPI), комментарии и вложения,
  самостоятельное закрытие с причиной и кнопка «напомнить о себе» с кулдауном.
- **Синхронизация GLPI → Telegram** — цикл опроса анонсирует новые заявки в
  группу техников и шлёт заявителю смены статусов / ответы техников. Курсоры
  хранятся в SQLite: рестарты не дублируют уведомления.
- **Действия техников** — кнопки Взять / Комментарий / Закрыть прямо на
  карточке в группе; тексты решения и комментария собираются в личке техника.
- **Тихие часы** — в нерабочее время несрочные уведомления копятся в очереди и
  доставляются утром пачкой; срочные проходят сразу; заявителю сообщается,
  когда команда реально увидит заявку.
- **Два языка** — все строки интерфейса на русском или английском
  (`BOT_LANGUAGE`).

## Требования

- **GLPI 11** (проверено на 11.0.4) с включённым **legacy REST API**
  (`apirest.php`) и сервисным аккаунтом с API-токеном. High-Level API GLPI 11
  (`/api.php`, OAuth2) *не* используется.
- **Python 3.11+**
- Исходящий HTTPS до `api.telegram.org` (учитывается `HTTPS_PROXY`). Входящие
  соединения не нужны — бот работает через long polling.
- Токен Telegram-бота (от [@BotFather](https://t.me/BotFather)) и группа
  техников.

## Установка

1. **Создайте бота**: @BotFather → `/newbot`, сохраните токен. Добавьте бота в
   группу техников и узнайте её chat id (например, через @getidsbot).

2. **Подготовьте GLPI**: включите API (*Настройки → Общие → API*), создайте
   сервисный аккаунт с правами на чтение пользователей/заявок и создание
   заявок/комментариев, сгенерируйте его **API-токен** (*настройки
   пользователя → API-токены*). App-Token при работе через localhost не
   обязателен.

3. **Установите бота** (от root на хосте GLPI):

   ```bash
   git clone https://github.com/snnrman/glpi-tgbot.git /opt/glpi-tgbot
   cd /opt/glpi-tgbot
   sudo bash deploy/install.sh
   ```

   Скрипт создаст сервисного пользователя `glpibot`, venv в
   `/opt/glpi-tgbot/venv`, каталог данных `/var/lib/glpi-tgbot` и systemd-юнит
   `glpi-tgbot.service`.

4. **Настройте**:

   ```bash
   sudo nano /var/lib/glpi-tgbot/.env    # впишите токены, см. таблицу ниже
   ```

5. **Запустите**:

   ```bash
   sudo systemctl restart glpi-tgbot
   journalctl -u glpi-tgbot -f           # JSON-логи
   ```

6. В Telegram: отправьте боту `/start`, привяжите аккаунт, создайте заявку.

## Конфигурация

Вся конфигурация — из переменных окружения (`/var/lib/glpi-tgbot/.env` под
systemd). См. [.env.example](.env.example).

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | ✅ | — | Токен бота от @BotFather |
| `TECH_GROUP_CHAT_ID` | для привязки | — | Telegram-группа, где подтверждается привязка и анонсируются заявки |
| `GLPI_API_URL` | ✅ | — | Базовый URL `apirest.php`, напр. `http://127.0.0.1/apirest.php` |
| `GLPI_APP_TOKEN` | — | пусто | App-Token GLPI; через localhost обычно не нужен |
| `GLPI_USER_TOKEN` | ✅ | — | API-токен сервисного аккаунта GLPI |
| `GLPI_TIMEOUT` | — | `20` | HTTP-таймаут запросов к GLPI, сек |
| `TECH_GROUP_ID` | — | — | Id группы GLPI, члены которой считаются техниками |
| `LINK_RECHECK_TTL` | — | `300` | Период перепроверки активности привязанного аккаунта, сек |
| `SYNC_INTERVAL` | — | `45` | Интервал опроса GLPI, сек |
| `REMIND_COOLDOWN_HOURS` | — | `4` | Мин. часов между напоминаниями по одной заявке |
| `UNASSIGNED_REMIND_HOURS` | — | `2` | Напоминать группе о неназначенных заявках старше N рабочих часов |
| `REMIND_INTERVAL_HOURS` | — | `3` | Мин. рабочих часов между повторными напоминаниями по заявке |
| `TZ` | — | системная | Часовой пояс бота (даты GLPI в UTC конвертируются в него) |
| `WORK_HOURS` | — | `09:00-18:00` | Рабочие часы для тихих часов |
| `WORK_DAYS` | — | `1-5` | Рабочие дни ISO, Пн=1..Вс=7 |
| `QUIET_MIN_URGENCY` | — | `4` | В нерабочее время: срочность ≥ этой идёт сразу (шкала GLPI 1–5) |
| `BOT_LANGUAGE` | — | `ru` | Язык интерфейса: `ru` или `en` |
| `WELCOME_MESSAGE` | — | — | Своё приветствие /start для привязанных (непривязанные всегда получают текст авторизации); как есть для обоих языков, HTML разрешён, `\n` — перенос строки |
| `CATEGORY_CACHE_TTL` | — | `600` | Кэш списка категорий, сек |
| `DB_PATH` | — | `/var/lib/glpi-tgbot/glpi-tgbot.sqlite3` | Путь к базе SQLite |
| `LOG_LEVEL` | — | `INFO` | Уровень логирования |
| `HTTPS_PROXY` | — | — | Опциональный исходящий прокси (httpx и aiogram) |

## Архитектура

```
bot/
  main.py            # входная точка: диспетчер, polling, sync-таск
  config.py          # pydantic-settings (только env)
  schedule.py        # модель рабочих часов для тихих часов
  timeutil.py        # даты GLPI в UTC -> локальное время
  middleware.py      # auth-гейт: только привязанные, авто-отвязка
  texts/             # все строки интерфейса (ru.py / en.py)
  glpi/
    client.py        # единственный модуль, ходящий по HTTP в GLPI
    models.py        # dataclass'ы заявок, пользователей, комментариев
  handlers/          # роутеры aiogram: привязка, /new, /tickets, действия техников
  services/
    sync.py          # цикл GLPI -> Telegram + очередь тихих часов
    notify.py        # рендер/отправка сообщений, edge cases Telegram
    attachments.py   # работа с файлами Telegram (лимит Bot API 20 МБ)
  db/
    schema.sql       # схема SQLite (привязки, курсоры, очереди)
    repo.py          # тонкий репозиторий над одним aiosqlite-соединением
deploy/              # systemd-юнит + скрипт установки
tests/               # pytest + respx (mock HTTP), живой GLPI не нужен
```

Ключевые решения:

- **Весь HTTP к GLPI — в `glpi/client.py`**: прозрачное обновление сессий
  (включая недокументированный ответ GLPI «400 на мёртвый токен»), ретраи с
  учётом идемпотентности, каждая ошибка — `GlpiError` с сырым ответом API.
- **Состояние — SQLite** (aiosqlite, WAL): привязки, курсоры синка, очередь
  тихих часов, кулдауны напоминаний. Рестарт не дублирует ни одно уведомление.
- **Группа техников — граница доверия**: привязка и опасные действия
  подтверждаются кнопками, работающими только внутри этой группы.
